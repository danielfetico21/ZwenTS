# RFC 0005: Optional Wire-style DI Codegen

- **Status:** Accepted
- **Created:** 2026-08-06
- **Accepted:** 2026-08-06
- **Depends on:** [RFC 0001](./0001-lightweight-typescript-backend.md)

---

## 1. Summary

ZwenTS keeps **explicit factory composition** as the default. Optional **Wire-like codegen** generates that composition from typed provider declarations so large graphs stay maintainable without runtime reflection.

**Runtime helper:** `composeProviders()` in `@zwents/core` — ordered, explicit, no magic.

**Codegen:** `zwen gen:wire` emits `container.gen.ts` from a `defineWire` manifest (`@zwents/cli/wire`). Parsing uses the classic TypeScript AST via `@typescript/typescript6` (TS 7.0 removed the programmatic API until 7.1).

## 2. Motivation

Hand-written `buildContainer()` is clear but verbose at scale. Nest-style runtime DI reintroduces reflection, cryptic cycles, and slow boot. Go’s [Wire](https://github.com/google/wire) shows the middle path: convenience at **build time**, plain functions at **runtime**.

## 3. Principles

1. Generated code is plain TypeScript — no container walk at boot.
2. Circular dependencies are **codegen errors**, not bootstrap exceptions.
3. Manual `composeProviders` / `buildContainer` always remain valid.
4. No `reflect-metadata`.
5. Dependencies are **explicit string keys** on `wire(factory, deps)` (phase 1 — no type-parameter inference yet).

## 4. Runtime API (`composeProviders`)

```ts
import { composeProviders } from "@zwents/core";

const ctx = composeProviders({
  db: () => createDb(process.env.DATABASE_URL!),
  users: (deps) => createUserService(deps.db as Db),
});
```

- Providers run **in object key order** (insertion order).
- Each factory receives the partially built bag.
- Duplicate keys throw.

## 5. Codegen contract

### 5.1 Input

```ts
// wire.ts
import { defineWire, wire } from "@zwents/cli/wire";
import { createDb } from "./infra/db.js";
import { createUserService } from "./users/service.js";

export default defineWire({
  providers: {
    db: wire(createDb, ["config"]),
    users: wire(createUserService, ["db"]),
  },
  seeds: ["config"],
  expose: ["db", "users"],
});
```

Flat form is also accepted:

```ts
export default defineWire({
  db: wire(createDb),
  users: wire(createUserService, ["db"]),
});
```

Factories referenced by `wire(...)` **must be imported** (not local closures).

### 5.2 Output

```ts
/* Generated by zwen gen:wire — do not edit by hand. */
import { createDb } from "./infra/db.js";
import { createUserService } from "./users/service.js";

export function buildContainer(config: unknown) {
  const db = createDb(config);
  const users = createUserService(db);
  return { db, users } as const;
}
```

### 5.3 Failure modes

| Issue | Result |
|-------|--------|
| Cycle A→B→A | `WireCodegenError` with cycle path |
| Missing binding | Error naming the missing key |
| Non-`wire()` entry | Parse error |
| Unimported factory | Parse error |

### 5.4 Non-goals (still)

- Request-scoped providers
- Runtime module graph
- Decorator providers
- Inferring deps from TypeScript parameter types (future)

## 6. CLI

```bash
zwen gen:wire --from ./src/wire.ts --out ./src/container.gen.ts
```

Example: `examples/notes-api` (`pnpm --filter @zwents/example-notes-api gen:wire`).

## 7. Compatibility

`composeProviders` signature is semver-stable. Generated file format may change until codegen reaches 1.0 — always regenerate in CI when you rely on it.
